# Парк узлов под одной панелью

Три машины: один управляющий узел, куда заходят операторы, и два краевых узла,
которые несут трафик. В конце добавление пользователя на любом из трёх — это
форма на одной странице, а журнал аудита управляющего узла записывает, на какой
узел ушло действие.

Ничего из этого не требует базы данных, брокера сообщений или второго бинарника.
На каждом узле уже работает панель; управляющий узел просто вызывает остальные.

Справочник по всем ключам:
[Advanced_settings/PANEL.ru.md](../Advanced_settings/PANEL.ru.md).
Готовые шаблоны: [`contrib/panel/`](../../contrib/panel/).

## Что нужно заранее

- Три хоста с установленным telemt. Ниже — `control.example.com`,
  `edge-fra-1.example.com`, `edge-sin-1.example.com`.
- DNS-имя на узел, которое разрешает управляющий узел. Адрес тоже подойдёт:
  сертификат агента пиннится по отпечатку, а не по имени.
- Часы, расходящиеся не больше чем на минуту. Подписанные запросы несут метку
  времени, и агент отвергает запрос вне `panel.cluster.clock_skew_secs`.
  Проверьте `timedatectl status`; если `System clock synchronized: no` — сначала
  почините это, иначе симптом будет выглядеть как неверный ключ.

## 1. Управляющий узел

Скопируйте [`contrib/panel/master.toml`](../../contrib/panel/master.toml) в
`/etc/telemt/config.toml` и замените все `CHANGE ME`. Существенная часть:

```toml
[server.api]
enabled = true
listen = "127.0.0.1:9091"
auth_header = "Bearer <head -c 32 /dev/urandom | base64>"
runtime_edge_enabled = true

[panel]
enabled = true
listen = "127.0.0.1:8443"
data_dir = "/etc/telemt/panel"
require_totp = false          # включается на шаге 6

[panel.cluster]
enabled = true
role = "master"
node_name = "control"
```

Опубликуйте её через TLS-фронт-прокси —
[`contrib/panel/Caddyfile.example`](../../contrib/panel/Caddyfile.example) или
[`nginx.conf.example`](../../contrib/panel/nginx.conf.example) — под отдельным
именем хоста. Не переиспользуйте имя, под которым работает WEB-транспорт: тот
origin должен выглядеть обычным сайтом, а этот несёт HSTS и форму входа.

Запустите telemt и прочитайте сгенерированный пароль:

```
$ systemctl start telemt
$ journalctl -u telemt -n 5 | grep -i panel
Panel bootstrap account created; the generated password is in this file
  path=/etc/telemt/panel/panel-bootstrap.txt username=admin

$ sudo cat /etc/telemt/panel/panel-bootstrap.txt
```

Войдите на `https://control.example.com/` как `admin`. Панель потребует новый
пароль прежде, чем станет доступно что-либо ещё. После этого удалите файл.

## 2. Краевой узел

Скопируйте [`contrib/panel/agent.toml`](../../contrib/panel/agent.toml) в
`/etc/telemt/config.toml` на `edge-fra-1`. Этот узел терминирует TLS сам,
поэтому выпустите сертификат:

```
$ sudo /path/to/contrib/panel/make-panel-cert.sh edge-fra-1.example.com /etc/telemt/panel
Certificate: /etc/telemt/panel/fullchain.pem
Private key: /etc/telemt/panel/privkey.pem
SHA-256:     a77c9d69…c022
```

Самоподписанный сертификат здесь — правильный ответ. Управляющий узел пиннит
именно этот сертификат по SHA-256, поэтому пин и есть идентичность, а
удостоверяющий центр не участвует. Запомните отпечаток — он встретится ещё раз.

Ключи, которые делают узел привязываемым:

```toml
[panel]
enabled = true
listen = "0.0.0.0:8443"

[panel.tls]
enabled = true
cert_path = "/etc/telemt/panel/fullchain.pem"
key_path = "/etc/telemt/panel/privkey.pem"

[panel.cluster]
enabled = true
role = "agent"
node_name = "edge-fra-1"
advertise_url = "https://edge-fra-1.example.com:8443"
allow_from = ["203.0.113.10/32"]     # адрес управляющего узла
```

`allow_from` — второй барьер перед поверхностью, которая и так подписана.
Оставляйте его пустым, только если адрес управляющего узла не постоянен.

Откройте порт 8443 управляющему узлу и больше никому:

```sh
ufw allow from 203.0.113.10 to any port 8443 proto tcp
```

Запустите telemt. Строка в логе подтверждает тот же отпечаток, что напечатал
скрипт:

```
Panel TLS certificate loaded fingerprint=a77c9d69…c022
Panel endpoint: https://0.0.0.0:8443/ cluster=true role="agent"
```

## 3. Прочитайте link-токен

Войдите в **собственную панель краевого узла** на
`https://edge-fra-1.example.com:8443/` — у неё своя первичная учётка, напечатанная
в её собственный лог. Откройте **Fleet → This node's link token → Reveal token**
и скопируйте значение:

```
telemt-node:eyJ2IjoxLCJpZCI6Im5vZGUtQlJRdXBzU3FjYl…
```

Одна непрозрачная строка, несущая четыре вещи: идентичность узла, адрес для
подключения, HMAC-ключ для подписи каждого запроса и отпечаток сертификата для
пиннинга. Поэтому она скрыта, пока её не запросят, и поэтому страница отдельно
печатает отпечаток — сверьте его с тем, что напечатал `make-panel-cert.sh`,
прежде чем куда-либо вставлять.

## 4. Привяжите узел

Обратно на управляющем узле: **Fleet → Link node**, вставьте токен, задайте имя
и тег, подтвердите.

Связь проверяется до сохранения. Управляющий узел подписывает `hello`, агент
отвечает своей идентичностью, и они сверяются — поэтому токен, вставленный не в
ту панель, узел за закрытым портом или ротированный ключ дают ошибку здесь, а не
при первом использовании. Диалог показывает версию, которой ответил узел, и
измеренное расхождение часов.

Повторите шаги 2–4 для `edge-sin-1`.

## 5. Пользуйтесь

Переключатель узлов над навигацией теперь показывает три узла, и все страницы
следуют за ним. Что стоит сделать один раз:

- **Overview** показывает таблицу парка: аптайм, соединения, отказы и число
  пользователей на узел, обновление каждые 30 секунд. Узел, переставший
  отвечать, сообщит об этом там раньше, чем кто-то откроет его страницу.
- **Users** на краевом узле создаёт пользователя на диске *этого* узла. Общего
  списка пользователей по парку нет: каждый узел владеет своим `[access.users]`,
  и панель явно показывает, какой из них вы правите.
- **Audit** на управляющем узле записывает каждое изменение вместе с узлом,
  куда оно ушло, поэтому `control.post /v1/users node=node-BRQ…` — это вся
  история о том, кто и где добавил пользователя.
- **Settings → Default node** выбирает, с какого узла открывается интерфейс.

## 6. Закройте доступ

Теперь, когда администратор существует и вошёл:

1. **Account → Second factor → Enrol authenticator** на управляющем узле.
   Сохраните десять кодов восстановления: они показываются один раз, хранятся
   только их хэши.
2. Поставьте `require_totp = true` в `[panel]` на управляющем узле и
   перезапустите. В этом порядке первый вход не потребует одновременно и
   подключения второго фактора, и смены пароля на одном экране.
3. Создайте персональные учётные записи в **Operators** вместо общего `admin`.
   `viewer` читает всё, `operator` дополнительно управляет пользователями и
   квотами, `admin` дополнительно получает конфигурацию и связи узлов.
4. Удалите `panel-bootstrap.txt` на каждом узле.
5. Убедитесь, что цепочка аудита сходится: **Audit → Verify chain**.

## Если что-то не так

`node_unreachable` на странице Fleet — проверьте узел через **⋯ → Probe now**;
показанная ошибка принадлежит самому транспорту. По убыванию вероятности:
`advertise_url` указывает на адрес, до которого управляющий узел не доходит; нет
правила файрвола; сертификат агента заменён и не совпадает с пином; `allow_from`
не включает управляющий узел.

`stale_timestamp` — часы разошлись больше, чем на `clock_skew_secs`. Чините
часы, а не расширяйте окно: окно — это время, в течение которого перехваченный
запрос остаётся пригодным для повтора.

`unknown_node` от узла, который точно привязан, — его link-ключ ротирован либо
`panel.json` пересоздан и идентичность сменилась. Привяжите заново свежим
токеном.

Остальное — в
[Advanced_settings/PANEL.ru.md § Если что-то не работает](../Advanced_settings/PANEL.ru.md#если-что-то-не-работает).

## Чего это не делает

- **Нет выдачи пользователей на весь парк.** Добавить пользователя на пять
  узлов — это пять действий или пять вызовов Control API. Каждый узел владеет
  своим файлом конфигурации, и панель не делает вид, что это не так.
- **Нет шаблонизации конфигурации.** Страница Config правит файл одного узла.
- **Агент не инициирует соединение.** Управляющий узел ходит к агентам, поэтому
  агент за NAT без доступного адреса привязать нельзя.
- **Нет депонирования секретов.** Ротация секрета пользователя показывает его
  один раз, на том узле, который его выпустил.
