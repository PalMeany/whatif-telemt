# Встроенная веб-панель

Панель — интерфейс оператора, вкомпилированный в бинарник `telemt`. Она отдаёт
одностраничное приложение, собственный JSON API и — когда включена федерация —
подписанный эндпоинт между узлами, позволяющий одному узлу управлять остальными.

Панель — **клиент Control API**. Каждое число, которое она показывает, и каждое
изменение, которое она делает, — это вызов `[server.api]` соответствующего узла,
поэтому включение панели ничего не меняет в поведении прокси.

```
браузер ──TLS──► панель (:8443) ──loopback──► Control API (:9091) ──► рантайм
                    │
                    └──подписанный HTTPS──► панель агента ──► его Control API
```

> **Это не то же самое, что `[fork.prometheus]`.** Тот раздел отдаёт одну
> read-only HTML-страницу с метриками на метрик-слушателе, по умолчанию по пути
> `/panel`. Этот раздел — интерфейс оператора: отдельный слушатель, собственная
> аутентификация и право менять пользователей и конфигурацию. Они независимы и
> могут работать вместе.

`[panel]` намеренно вынесен **не** под `[fork]`, в отличие от всего остального,
что добавляет форк. Обоснование —
в [CHANGES-FROM-UPSTREAM.md](../../CHANGES-FROM-UPSTREAM.md#operator-features):
панель не меняет поведение прокси, поэтому у выключателя `[fork]` нет причины
забирать вместе с собой административный интерфейс оператора.

## Быстрый старт

```toml
[server.api]
enabled = true
listen = "127.0.0.1:9091"
auth_header = "Bearer <длинная случайная строка>"

[panel]
enabled = true
listen = "127.0.0.1:8443"
```

Запустите telemt и посмотрите в лог:

```
Panel bootstrap account created; the generated password is in this file
  path=/etc/telemt/panel/panel-bootstrap.txt username=admin
Panel endpoint: http://127.0.0.1:8443/
```

Войдите как `admin` с этим паролем. Панель требует сменить его прежде, чем
станет доступно что-либо ещё; после этого файл можно удалить.

Поставьте слушатель за TLS-фронт-прокси или терминируйте TLS внутри процесса:

```toml
[panel]
enabled = true
listen = "0.0.0.0:8443"

[panel.tls]
enabled = true
cert_path = "/etc/telemt/panel/fullchain.pem"
key_path  = "/etc/telemt/panel/privkey.pem"
```

Немаршрутизируемый `panel.listen` без `panel.tls.enabled` отвергается при
старте, если только `panel.trusted_proxies` не называет фронт-прокси вне этого
хоста. Cookie сессии — `HttpOnly; Secure; SameSite=Strict`, а `Secure`-cookie
поверх открытого HTTP на маршрутизируемом адресе — конфигурация, которую панель
не примет.

## Конфигурация

### `[panel]`

| Ключ | Тип | По умолчанию | Значение |
| --- | --- | --- | --- |
| `enabled` | `bool` | `false` | Включает слушатель панели. |
| `listen` | `string` (`IP:PORT`) | `127.0.0.1:8443` | Адрес слушателя. |
| `data_dir` | `string` | `<каталог конфига>/panel` | Хранит store, журнал аудита и первичную учётку. При заданном `general.data_path` — `<data_path>/panel`. |
| `whitelist` | `CIDR[]` | `[]` | Список разрешённых источников для всего слушателя. Пустой — любой источник. |
| `trusted_proxies` | `CIDR[]` | loopback | Фронт-прокси, которым разрешено сообщать адрес клиента через `X-Forwarded-For`. |
| `control_api_url` | `string` | выводится | Базовый URL Control API этого узла. Выводится из `server.api.listen`, неуказанный адрес отображается на loopback. Допускается только `https` либо `http` на loopback-хост. |
| `control_api_token` | `string` | `server.api.auth_header` | Значение `Authorization` для Control API. |
| `session_ttl_secs` | `u64` | `43200` | Абсолютное время жизни сессии. Диапазон `[60, 2592000]`. |
| `session_idle_timeout_secs` | `u64` | `1800` | Таймаут бездействия. Диапазон `[60, session_ttl_secs]`. |
| `max_sessions_per_operator` | `usize` | `8` | Одновременных сессий на оператора. Диапазон `[1, 128]`. |
| `max_sessions_total` | `usize` | `512` | Одновременных сессий на всех операторов. |
| `login_max_attempts` | `u32` | `5` | Неудач до блокировки. Диапазон `[1, 100]`. |
| `login_lockout_secs` | `u64` | `900` | Длительность блокировки. Диапазон `[1, 86400]`. |
| `password_min_length` | `usize` | `12` | Минимальная длина пароля. Диапазон `[8, 256]`. |
| `password_hash_iterations` | `u32` | `600000` | Итерации PBKDF2-HMAC-SHA256. Диапазон `[100000, 5000000]`. |
| `require_totp` | `bool` | `false` | Каждый оператор обязан подключить второй фактор, прежде чем получит доступ к чему-либо ещё. |
| `request_body_limit_bytes` | `usize` | `262144` | Максимальный размер тела запроса к панели. Диапазон `[1024, 8388608]`. |
| `max_connections` | `usize` | `256` | Одновременных соединений. Диапазон `[1, 65536]`. |
| `header_read_timeout_ms` | `u64` | `10000` | Дедлайн на чтение заголовков запроса и на TLS-рукопожатие. |
| `request_timeout_ms` | `u64` | `30000` | Дедлайн на обслуживание одного запроса. |
| `audit_enabled` | `bool` | `true` | Пишет каждое изменяющее действие в журнал аудита с цепочкой хэшей. |
| `audit_retention_days` | `u64` | `90` | Сколько дней хранятся ротированные сегменты. |
| `audit_max_bytes` | `u64` | `67108864` | Размер журнала, при котором происходит ротация. |

### `[panel.tls]`

| Ключ | Тип | По умолчанию | Значение |
| --- | --- | --- | --- |
| `enabled` | `bool` | `false` | Терминирует TLS внутри процесса. |
| `cert_path` | `string` | `""` | PEM-цепочка сертификатов, листовой первым. |
| `key_path` | `string` | `""` | PEM-ключ: PKCS#8, PKCS#1 или SEC1. |

Оба файла проверяются на читаемость до сброса привилегий, поэтому неверный путь
приводит к отказу при старте, а не при первом запросе.

### `[panel.cluster]`

| Ключ | Тип | По умолчанию | Значение |
| --- | --- | --- | --- |
| `enabled` | `bool` | `false` | Включает федерацию. |
| `role` | `standalone` \| `master` \| `agent` \| `master-agent` | `standalone` | Роль узла. При `enabled = true` роль обязана отличаться от `standalone`. |
| `node_name` | `string` | имя хоста | Отображаемое имя в списке узлов мастера. |
| `advertise_url` | `string` | `""` | Базовый URL, по которому мастер достучится до этого узла. `https` либо `http` на loopback. Обязателен для выпуска link-токена. |
| `allow_from` | `CIDR[]` | `[]` | Сети, которым разрешено обращаться к `/cluster/v1`. Пустой — любой источник; подпись всё равно проверяется. |
| `request_timeout_ms` | `u64` | `10000` | Дедлайн одного исходящего запроса к узлу. Диапазон `[1000, 120000]`. |
| `clock_skew_secs` | `u64` | `60` | Допустимое расхождение часов мастера и агента. Диапазон `[5, 600]`. |
| `nonce_capacity` | `usize` | `8192` | Сколько nonce хранит окно защиты от повтора. Диапазон `[256, 1048576]`. |
| `poll_interval_secs` | `u64` | `30` | Интервал фоновой проверки связанных узлов. Диапазон `[5, 3600]`. |

`[panel]` принадлежит процессу: слушатель биндится, сертификат читается, store
открывается один раз при старте. Перезагрузка конфигурации сообщает `panel` в
`deferred_process_fields`, и чтобы применить изменение, нужен рестарт.

## Что показывает интерфейс

Каждая страница читает Control API того узла, который выбран переключателем над
навигацией. Смена узла заменяет данные, а не смешивает их.

| Страница | Читает | Требует |
| --- | --- | --- |
| Overview | `/v1/stats/summary`, `/v1/health/ready` и сводку по всем узлам | — |
| Users | `/v1/users` и пользовательские команды | — |
| Traffic | `/v1/runtime/connections/summary`, `/v1/stats/zero/all`, `/v1/stats/users/active-ips` | `runtime_edge_enabled` для лидербордов |
| Middle-End | `/v1/runtime/me-pool-state`, `me-quality`, `me-selftest`, `/v1/stats/me-writers`, `/v1/stats/dcs`, `/v1/stats/minimal/all` | `general.use_middle_proxy` |
| Upstreams | `/v1/stats/upstreams`, `/v1/runtime/upstream-quality` | — |
| Security | `/v1/security/posture`, `/v1/security/whitelist`, `/v1/runtime/tls-fingerprints`, `/v1/runtime/nat-stun` | `runtime_edge_enabled` для отпечатков |
| Runtime | `/v1/system/info`, `/v1/runtime/gates`, `/v1/runtime/initialization`, `/v1/limits/effective` и команды перезагрузки | — |
| Events | `/v1/runtime/events/recent` | `runtime_edge_enabled` |
| Config | `/v1/config` | роль admin |
| Fleet, Operators, Audit, Settings | собственный store панели | — |

Часть этих эндпоинтов отвечает `{ "enabled": false, "reason": "..." }` вместо
полезной нагрузки, когда стоящая за ними функция выключена. Панель показывает
причину, которую назвал сам узел, а не пустую таблицу, чтобы «здесь ничего нет»
и «вы это не включили» никогда не выглядели одинаково:

```toml
[server.api]
enabled = true
# Лидерборды соединений, TLS-отпечатки и лента событий.
runtime_edge_enabled = true
```

Включение стоит ограниченного кольцевого буфера и кэшируемой агрегации на пути
запроса к Control API; на плоскости данных не меняется ничего.
`runtime_edge_top_n` задаёт число строк в лидербордах,
`runtime_edge_events_capacity` — глубину кольца событий.

## Федерация

В парке один **мастер** и любое число **агентов**. Отдельного бинарника агента и
постоянного соединения нет: на каждом связанном узле уже работает панель, и её
эндпоинт `/cluster/v1` — это и есть вся удалённая поверхность.

### На агенте

```toml
[panel]
enabled = true
listen = "0.0.0.0:8443"

[panel.tls]
enabled = true
cert_path = "/etc/telemt/panel/fullchain.pem"
key_path  = "/etc/telemt/panel/privkey.pem"

[panel.cluster]
enabled = true
role = "agent"
node_name = "edge-fra-1"
advertise_url = "https://edge-fra-1.example.com:8443"
allow_from = ["203.0.113.10/32"]   # адрес мастера
```

Откройте **Fleet → This node's link token → Reveal token** и скопируйте
значение. Токен — одна непрозрачная строка, несущая идентичность узла, адрес для
подключения, HMAC-ключ и отпечаток сертификата для пиннинга.

### На мастере

```toml
[panel.cluster]
enabled = true
role = "master"
node_name = "control"
```

Откройте **Fleet → Link node**, вставьте токен и подтвердите. Мастер проверяет
связь до того, как сохранит её: недоступный узел или неверный ключ дадут ошибку
в момент вставки, а не при первом использовании.

После этого на каждой странице появляется переключатель узлов, и все вызовы
Control API идут туда, куда он указывает.

### Как аутентифицируется запрос между узлами

Каждый запрос несёт четыре заголовка и подпись HMAC-SHA256 по каноническому
описанию запроса:

```
TELEMT-CLUSTER-V1\n<метод>\n<путь+query>\n<id целевого узла>\n<unix ms>\n<nonce>\n<sha256(тело) hex>
```

| Заголовок | Смысл |
| --- | --- |
| `X-Telemt-Node` | Идентификатор узла, которому адресован запрос. |
| `X-Telemt-Timestamp` | Unix-миллисекунды; должны укладываться в `clock_skew_secs`. |
| `X-Telemt-Nonce` | Канонический base64url без паддинга, расходуется один раз в окне повтора. |
| `X-Telemt-Signature` | Подпись, base64url без паддинга. |

Подпись связывает метод, цель, идентичность узла, время, nonce и точные байты
тела, поэтому перехваченный запрос нельзя переиграть ни на другом маршруте, ни
против другого узла, ни после закрытия окна. Подпись проверяется **до** того,
как nonce будет израсходован, — иначе неаутентифицированный вызывающий сжигал бы
nonce, которые собирается использовать легитимный мастер.

Транспортная безопасность независима: мастер пиннит листовой сертификат агента
по SHA-256, если токен его несёт. Именно поэтому самоподписанный сертификат на
агенте — защитимая конфигурация.

`POST /panel/api/nodes/link-token/rotate` выпускает новый ключ на агенте. Все
существующие связи с ним перестают работать и должны быть установлены заново.

## Роли

| Роль | Чтение | Пользователи прокси | Конфиг, перезагрузки | Связи узлов, учётки панели |
| --- | --- | --- | --- | --- |
| `viewer` | да | нет | нет | нет |
| `operator` | да | да | нет | нет |
| `admin` | да | да | да | да |

Проверка выполняется по паре «метод + путь» самого Control API, и маршрут без
явного правила доступен только администратору. Смена роли, пароля или флага
`disabled` немедленно завершает все сессии этой учётной записи.

## Модель безопасности

**Аутентификация.** Пароли — PBKDF2-HMAC-SHA256 с индивидуальной солью, по
умолчанию 600 000 итераций, вычисляются в блокирующем пуле, поэтому вход никогда
не тормозит рабочий поток рантайма. Учётка, сохранённая с меньшим числом
итераций, пересчитывается при следующем успешном входе. За неизвестный аккаунт
всё равно платится одно вычисление, поэтому время ответа не выдаёт существование
учётной записи.

**Второй фактор.** RFC 6238 TOTP, HMAC-SHA1, шаг 30 секунд, шесть цифр,
допускается расхождение в один шаг. При подключении выпускается десять
одноразовых кодов восстановления; хранятся только их SHA-256.

**Сессии.** Только в памяти — рестарт разлогинивает всех. Реестр индексируется
SHA-256 от cookie, поэтому никогда не хранит значение, которое можно
переиграть. Действуют и абсолютный срок жизни, и таймаут бездействия, а
переполнение лимита вытесняет самую старую сессию.

**CSRF.** Каждый запрос к API панели обязан нести `X-Telemt-Panel: 1` — кросс-
доменный вызывающий не может выставить этот заголовок без предварительного
запроса, на который панель никогда не отвечает. Любой изменяющий запрос
дополнительно обязан нести `X-Telemt-Csrf` сессии, сравниваемый за постоянное
время. Заголовок `Origin`, если он есть, должен совпадать с `Host`.

**Ограничение попыток.** Неудачные входы считаются отдельно по имени учётной
записи и по адресу источника. Первый счётчик мешает подбирать пароль с
меняющихся адресов, второй — перебирать имена с одного адреса.

**Заголовки ответов.** Каждый ответ несёт `Content-Security-Policy`
(`default-src 'none'`, без inline-скриптов и внешних источников),
`X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`,
`Referrer-Policy: no-referrer`, `Cross-Origin-Opener-Policy`,
`Cross-Origin-Resource-Policy`, `Permissions-Policy`, запрещающий все мощные
возможности, и `Cache-Control: no-store`. Поверх TLS добавляется
`Strict-Transport-Security`.

**Аудит.** Каждое изменяющее действие добавляет одну JSON-строку, SHA-256
которой покрывает и саму запись, и хэш предыдущей. Удаление или правка строки
ломает проверку начиная с этого места. **Audit → Verify chain** пересчитывает
цепочку по всем сохранённым сегментам, включая ротированные. Чтения намеренно
не записываются.

Поля прообраза разделены не переводом строки, а длиной. Некоторые из них несут
текст, выбранный вызывающей стороной, — присланное имя учётной записи,
проксируемый путь, — и разделитель, который может встретиться внутри значения,
позволил бы двум разным записям дать одинаковый хэш. Ровно это свойство цепочка
и должна исключать.

Присланное имя учётной записи, которому **не** соответствует ни один оператор, в
журнал не пишется. Операторы регулярно вставляют пароль в поле имени, и журнал,
записывающий присланное как есть, превращает каждую такую опечатку в живую
учётную запись, доступную всем, кто может читать журнал. В записи остаётся
`actor: "<unknown>"` и двенадцатисимвольный дайджест присланного имени — этого
достаточно, чтобы соотнести повторные попытки:

```json
{"seq":1,"actor":"<unknown>","action":"auth.login","result":"unknown_account",
 "address":"203.0.113.9","detail":"submitted_name_digest=ffb3039dada4"}
```

Имена, которые соответствуют существующей учётке, пишутся как есть: имя учётной
записи не секрет. Каждое поле ограничено 512 символами, поэтому тот, кто может
дотянуться до маршрута входа, не превратит журнал аудита в усилитель записи.

**Файлы.** Store и журнал аудита пишутся через временный файл в том же каталоге
и переименование, с правами `0600` в каталоге `0700`. Если store доступен на
чтение кому-то кроме владельца, панель предупреждает об этом при старте.

**Область проксирования.** Проксируется только документированная поверхность
`/v1` Control API, а путь с сегментами `.` или `..` отвергается. Браузер нельзя
превратить в универсальный форвардер к тому, что ещё отвечает на адресе Control
API.

## API панели

Всё под `/panel/api` требует cookie сессии и клиентского заголовка; изменяющие
запросы — дополнительно CSRF-токена.

| Метод | Путь | Роль | Назначение |
| --- | --- | --- | --- |
| `POST` | `/panel/api/session` | — | Вход. Тело: `username`, `password`, опционально `totp` или `recovery_code`. |
| `GET` | `/panel/api/session` | любая | Текущая сессия. |
| `DELETE` | `/panel/api/session` | любая | Выход. |
| `GET` | `/panel/api/bootstrap` | любая | Версия, идентичность узла, роль в федерации, оператор. |
| `POST` | `/panel/api/account/password` | любая | Смена своего пароля; завершает все прочие сессии. |
| `GET`/`POST`/`PUT`/`DELETE` | `/panel/api/account/totp` | любая | Состояние второго фактора, подключение, подтверждение, снятие. |
| `GET`/`DELETE` | `/panel/api/account/sessions` | любая | Список своих сессий; завершение всех, кроме текущей. |
| `GET`/`POST` | `/panel/api/operators` | admin | Список и создание учётных записей панели. |
| `PATCH`/`DELETE` | `/panel/api/operators/{id}` | admin | Роль, флаг `disabled`, пароль, сброс второго фактора, удаление. |
| `GET` | `/panel/api/nodes` | любая | Локальный узел и все связанные, со статусом. |
| `POST` | `/panel/api/nodes` | admin | Связать узел по токену. |
| `PATCH`/`DELETE` | `/panel/api/nodes/{id}` | admin | Переименование, теги, смена адреса, отвязка. |
| `POST` | `/panel/api/nodes/{id}/probe` | любая | Немедленная проверка узла. |
| `GET` | `/panel/api/nodes/link-token` | admin | Link-токен этого узла (только для ролей агента). |
| `POST` | `/panel/api/nodes/link-token/rotate` | admin | Выпустить новый link-ключ. |
| `GET` | `/panel/api/overview` | любая | Сводка по всем узлам. |
| `GET` | `/panel/api/audit` | admin | Последние записи аудита. |
| `GET` | `/panel/api/audit/verify` | admin | Пересчёт цепочки хэшей. |
| `GET`/`PATCH` | `/panel/api/settings` | любая / admin | Настройки; смена узла по умолчанию требует admin. |
| любой | `/panel/api/control/v1/...` | по маршруту | Проксирование в Control API выбранного узла. |

Узел выбирается через `?node=<id>` или заголовок `X-Telemt-Panel-Node`. `local`
и собственный идентификатор узла означают узел, на котором работает панель.
Конверт Control API, включая `revision`, возвращается без изменений.

`GET /healthz` не требует сессии и отвечает `ok` для liveness-пробы.

## Сборка интерфейса

Собранный бандл в `panel-ui/dist` закоммичен, поэтому `cargo build` сразу даёт
бинарник со встроенным интерфейсом. Чтобы изменить его:

```bash
npm --prefix panel-ui ci
npm --prefix panel-ui run build
cargo build --release
```

`build.rs` обходит `panel-ui/dist` и генерирует таблицу ассетов; сборка без
этого каталога всё равно даёт рабочий API панели и страницу с объяснением, что
бандл отсутствует.

Разработка интерфейса против работающего узла:

```bash
npm --prefix panel-ui run dev   # проксирует /panel/api на 127.0.0.1:8443
```

## Эксплуатация

- Панели нужен `server.api.enabled = true`; сочетание отвергается при старте с
  явным сообщением.
- `data_dir` должен быть доступен на запись сервисной учётной записи и
  создаётся при первом старте **после** сброса привилегий. Штатный systemd-юнит
  уже перечисляет `/etc/telemt` в `ReadWritePaths`, что покрывает расположение
  по умолчанию; развёртывание вручную должно выдать это право явно, иначе
  панель откажется стартовать с указанием пути в ошибке.
- `server.api.read_only = true` оставляет все представления и отвергает любые
  изменения. Страница конфигурации сообщает об этом, а не падает на каждом
  действии.
- Представления runtime-edge — лидерборды соединений, TLS-отпечатки, лента
  событий — требуют `server.api.runtime_edge_enabled = true` на нужном узле.
- Удаление `panel.json` сбрасывает панель: новая идентичность узла, новый
  link-ключ и новая первичная учётка. Все существующие связи придётся
  устанавливать заново.
- Потеря всех административных паролей означает удаление `panel.json` и
  повторную привязку; пути восстановления мимо файловой системы нет.

## Если что-то не работает

**Процесс отказывается стартовать.** Любая ошибка в конфигурации панели фатальна
при старте, а не при первом запросе, и сообщение называет ключ:

| В сообщении | Причина |
| --- | --- |
| `panel.enabled requires server.api.enabled` | Панели нечем управлять: Control API выключен. |
| `panel.trusted_proxies must name the TLS front proxy` | `listen` не loopback, при этом ни `panel.tls.enabled`, ни доверенный прокси вне хоста не заданы. |
| `panel.tls.cert_path is not a readable file` | Проверяется до сброса привилегий: неверный путь или сервисная учётка не может прочитать файл. |
| `failed to create panel data directory` | `data_dir` недоступен на запись учётной записи, под которую сброшен процесс. |
| `panel listener could not bind` | Адрес занят либо привилегированный порт без `CAP_NET_BIND_SERVICE`. |

**Страница грузится, но каждый запрос падает с `missing_client_header`.** Что-то
между браузером и панелью вырезает `X-Telemt-Panel`. Фронт-прокси, фильтрующий
неизвестные заголовки, должен пропускать `X-Telemt-Panel`, `X-Telemt-Csrf` и
`X-Telemt-Panel-Node`.

**Вход проходит, а следующий запрос — `401`.** Cookie сессии помечена `Secure`,
поэтому браузер её не сохранит, если не считает источник доверенным. Обращайтесь
по HTTPS либо на `http://localhost` / `http://127.0.0.1`, которые браузеры
считают безопасным контекстом. Открытый HTTP на внешнем адресе работать не
будет, и конфигурация, дающая его, всё равно отвергается.

**`cross_origin` на каждом запросе.** `Origin`, который присылает браузер, не
совпадает с `Host`, который видит панель. Фронт-прокси, переписывающий `Host`,
должен передавать публичный — `proxy_set_header Host $host;` в nginx, как в
шаблоне [`contrib/panel/nginx.conf.example`](../../contrib/panel/nginx.conf.example).

**Связанный узел показывает `node_unreachable`.** Проверьте его через
**Fleet → ⋯ → Probe now**; в ошибке будет сообщение самого транспорта. Частые
причины по убыванию: `advertise_url` агента указывает на адрес, до которого
мастер не доходит; сертификат агента заменён и больше не совпадает с
зафиксированным отпечатком (перепривяжите или снимите пин через **Fleet → ⋯**);
`panel.cluster.allow_from` на агенте не включает адрес мастера.

**`stale_timestamp` от агента.** Часы разошлись больше, чем на
`panel.cluster.clock_skew_secs`. Чините часы: расширение окна расширяет и время,
в течение которого перехваченный запрос остаётся пригодным для повтора.

**`unknown_node` от узла, который точно привязан.** Link-ключ агента был
ротирован либо его `panel.json` пересоздан и идентичность сменилась. И то и
другое требует повторной привязки свежим токеном.

**Интерфейс пустой, а API работает.** Бинарник собран без `panel-ui/dist`.
`GET /panel/api/bootstrap` вернёт `"bundled_ui": false`, а оболочка скажет об
этом вместо пустой страницы.

**Всё только на чтение, хотя учётка — администратор.** Control API узла в
режиме read-only. Проверьте `server.api.read_only`; страница Security показывает
это в разделе Posture.
